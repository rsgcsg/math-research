# 原生证明流完整性：一次可复现的导出问题与严格拒绝

2026-09-28。本节是证明生产链的工程校准，不是新数学色数结论。
仅报告归档Linux轮子python-sat 1.9.dev15内的CaDiCaL 1.9.5，不推断所有版本存在同一问题。
官方API把 `with_proof/get_proof` 作为DRUP导出接口；本次实际检查了安装版本的实现，
其中get_proof读取临时文件，但没有先调用CaDiCaL的内部证明刷新接口。

## 最小实测

两个矛盾例子分别是 `[1],[-1]` 以及四个二变量完整二元子句。
求解器都返回否定；立即get_proof()都得到空列表。
调用该版本原生 `flush_proof_trace(false)` 后，第一个得到真正的空子句记录，
第二个得到两个单位推导及空子句。两份结果另由不依赖求解器的Python RUP检查通过。
逐项输出与安装源码指纹在 `certificates/full15_proof_export_reproducer.json`。

大查询同样观测到未刷新尾部。例如三等权η恒等查询的磁盘长度从3801779增加到3802082字节。
所有六个大查询的刷新前字节流都不能被严格完整解析；刷新后快照可以。
这些是当前轮子的实测，不由单个小例外推到其他版本。

另一个独立解析校准：安装版本的 `_proof_bin2text(bytearray(b'a'))` 返回`['0']`，
即把只有“新增子句”标记但缺少终止符的截断流解释为空子句。
新解析器拒绝这个输入，也拒绝截断varint、缺失终止符、非法标记和零变量。
即使得到一个文本空子句，也仍必须从真实初始子句通过单位传播证明，不能信任解析结果。

## 修复及范围

`closed_binary_proof.py`只在明确匹配的PySAT版本、CaDiCaL195类及原生导出符号存在时运行，
否则停止；它通过原生公开flush方法先刷出内部缓冲，再读取完整快照。
读取不调用strip，不对截断记录补终止符或补空子句。
析构可能追加删除记录，本次证据使用显式刷新时刻的快照，不使用析构后的额外尾部。
文件描述符复制用于保持文件生命周期，不将“复制fd”误当成刷新证明缓冲。

这是生产器侧的版本限定适配器，涉及本地原生ABI，不是跨平台通用库。
独立验证 `make check-full15-support` 不执行此适配器，不加载PySAT/CaDiCaL，也不运行C++提取器。
任何证明导出/解析失败均留下未认证状态，不能解释为另一份数学反证。
此前已通过独立RUP重放的证据不因此失效；历史未认证否定也不自动获得认证。
